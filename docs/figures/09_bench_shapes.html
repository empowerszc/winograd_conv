⑨ 基准用例集：59 个形状

七个小节、59 行；每个小节对应一个待验证的假设，而不是随机堆形状。

0159 个形状怎么来的

不是随机采样：七个小节各自回答一个假设。

节验证什么
Case 0-8与历史 F44/F22 的 9 case 数据直接接轨
ResNet50 3×3 s1真实 CNN：mb=1 小负载 + mb=4；含降维 bottleneck 与 2048 深通道
VGG16 3×3 s1224² 大图小通道、14²/7² 深通道
Lightweight轻量网络常见形状，最小负载区间
Large batchmb=8–32：若大负载仍赢，说明是系统性优势而非固定开销摊薄
Fixed-overhead极小负载 + 高 iteration，隔离固定开销与调度成本
tiles × IC 网格mb=4、OC=IC、tiles∈{25,100,400,1600} × IC∈{48,96,192,384} 的全组合

02tiles × IC 网格：加速比的空间结构

颜色 = 对 OpenBLAS 的加速比；越靠右下越高。

读图：左上角（25 tiles、IC=48）只有 1.19x，右下角（1600 tiles、IC=384）达到 3.02x； 沿「tile 数↑」方向（固定 IC=48）从 1.19 → 1.59 → 1.66 → 1.71， 沿「IC↑」方向（固定 25 tiles）从 1.19 → 1.66 → 1.26 → 1.65。 两个方向都能抬升，说明收益来自摊薄固定开销 + GEMM 规模变大，而不是某个单一形状的偶然读数。 悬停可看到重复格点的两次测量值。

03形状参数的含义

所有行都是 stride=1、group=1、3×3、pad=1——这是 F(4,4,3,3) 的适用域。

量计算为什么重要
tile 数ceil(ih/4)² × mb每 tile 做 36 个 GEMM；tile 越多，GEMM 的 n 越大、固定开销越摊薄
IC输入通道GEMM 的 K 维；也是输入变换的数据量，决定 SVE 谓词利用率（IC=48 只用到 3/4 个寄存器）
OC输出通道GEMM 的 N 维；SME 路径按 64 一块（4 个 ZA tile），OC%64 决定尾块浪费
mbbatch线性放大 tile 数，是「大负载」的主要来源
注意：59 行里 4 个格点与 Case 0-8 刻意重叠 （如 4,192,40²,192 出现两次）。它们的 GEMM 读数一致、内存步可差 65%+， 是本套用例自带的噪声探针。

04怎么跑这套用例

同一条 CSV 同时喂给我们、oneDNN e2e 与 benchdnn。

# 正确性门（FAIL 即中止）
./build/bench_winograd --sve --nhwc --verify --threads 16 shapes/conv_all.csv

# 全量计时：1/8/16/32/38 线程
./build/bench_winograd --sve --nhwc --threads 1,8,16,32,38 shapes/conv_all.csv

# 转成 benchdnn 描述符（mb4_ic192_ih40iw40_oc192_oh40ow40_kh3kw3_sh1sw1_ph1pw1）
bash tools/gen_benchdnn_list.sh

# oneDNN 侧两列：强制 WINO 与 auto
bash tools/onednn/run_benchdnn.sh --winograd
bash tools/onednn/run_benchdnn.sh

CSV 全表：shapes/conv_all.csv；分节说明：shapes/README.md； 对照工具：tools/onednn/。
