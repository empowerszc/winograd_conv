③ SME FMOPA GEMM

把 36 个小切片直接映射到 ZA 二维累加器：行 = 16 个 OC、列 = 16 个 tile、4 个 tile = 64 个 OC。

01为什么需要专用内核

Winograd 把卷积变成 36 个「M 小、K 短、调用密」的小 GEMM，通用 BLAS 的固定开销在这里被放大。

切片特征59 形状集范围对通用 GEMM 的影响
切片数 n_multis36（固定）每次调用都有进入/退出 + 打包开销
M = tile 数4 … 31367² 图像只有 4 个 tile，分块填不满
N = OC16 … 512小 OC 时不足一个向量宽度
K = IC16 … 2048小 IC 时流水线填不满
t1 下这类小切片的有效吞吐只有几十 GFLOPS，而单核 SME fmopa 探针能到约 2 TFLOPS/核。 差距不在「GEMM 写得快不快」，而在执行模型是否匹配矩阵形态。

02布局：行 = OC，列 = tile

这个方向不是随手选的 —— 它决定 drain 出来的 64 B 能不能直接写进 M_buf。

03drain：64 条切片，零转置

04微内核

每轮 4 条 fmopa = 4 × 256 = 1024 次 FMA，配 5 次 64 B 加载 → 约 6.4 FLOP/byte。

; 一次窗口：4 个 ZA tile，K 循环每轮 4 条 fmopa
smstart
ptrue   p0.s
zero    {za0.s, za1.s, za2.s, za3.s}
1:
ld1w    {z16.s}, p0/z, [x9]          ; A: 16 个 tile 在同一个 ic 上的 U
ld1w    {z17.s}, p0/z, [x10]         ; B: OC 块 0 @ ic
ld1w    {z18.s}, p0/z, [x10, #1, MUL VL]
ld1w    {z19.s}, p0/z, [x10, #2, MUL VL]
ld1w    {z20.s}, p0/z, [x10, #3, MUL VL]
fmopa   za0.s, p0/m, p0/m, z16.s, z17.s
fmopa   za1.s, p0/m, p0/m, z16.s, z18.s
fmopa   za2.s, p0/m, p0/m, z16.s, z19.s
fmopa   za3.s, p0/m, p0/m, z16.s, z20.s
add     x9,  x9,  #64               ; A 的 k 步进 = 16 tile × 4 B
add     x10, x10, bstep             ; B 的 k 步进 = OC64 × 4 B
cmp / add / b.lt
; drain: 64 条 str za → 直接落 M_buf 的行

05结果与边界

绑核口径，59 形状，同一二进制只切环境变量。

纵轴为 log₂ 刻度，基准线 1.0；绿色 = SME 更快，红色 = KML 更快。逐形状数值与胜负归因见 docs/sme_fmopa_gemm.md §5。

优势区间

小空间 + 深通道（7²/14²）：M 再小也不损失外积利用率，KML 在 M=4 时只剩 20–22 GFLOPS， SME 最高 2.2x；大空间（160²/224²）在 t16 下最高 1.7x。

劣势区间

小空间 + 大 OC/IC：28² 的尾组只有 1 个有效 tile（ZN 利用率 6%）， 每个窗口固定 64 条 drain，浪费与 K 无关；t16 下 tile 少的形状并行度只来自 36 个切片。

06一个代价高昂的 ABI 陷阱

现象极具误导性：数据完全正确，但计时输出 inf。

smstart/smstop 切换流式模式时，所有 SVE z 寄存器与谓词都变成 UNPREDICTABLE； 而 AAPCS64 的 callee-saved 约定是 d8–d15。当时的 clobber 列表只写了实际用到的 z16–z20 与 p0，编译器以为 d11 里活着的常量 1e6 仍然有效 —— 一次调用返回后它被清零，ticks / 1e6 变成 inf。 -O0 不复现，独立的 minwin 小程序也不复现。

规则：任何内含 smstart/smstop 的内联汇编， clobber 必须覆盖 d8–d15 与 p1–p15；只写「自己用到的寄存器」是不够的。 完整定位过程见 docs/sme_fmopa_gemm.md §6。
