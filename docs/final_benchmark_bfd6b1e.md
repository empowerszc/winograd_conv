# 终局基准：arm_gemm 后端 vs OpenBLAS（59 形状，同作业 A/B）

> **测量**：2026-08-28，node03，`sbatch -w node03 --exclusive`，单作业内 arm/OB/旧码三侧对照
> （diag_ab.sh v2.2，commit bfd6b1e + f3367e7）。
> 16 线程，`OMP_PROC_BIND=close OMP_PLACES=cores`，频探首尾 10×1999 / 598×2000 MHz 稳定无漂移。
> 读法：**加速比 = OB / 我们，>1 表示我们快**；同作业内比较才有效（跨作业存在 3~7x 性能态，见 perf_engine_sweep.md 作废说明）。
> 我们侧 = `WINO_GEMM_VERIFY` 通过的正确性门之后、`build/`（arm_gemm 53.1.0, SVE-512）二进制。

## 结论前置

- **59/59 全胜**（修复前基线 47/59）；geomean 加速比 **1.99x**；合计 321.9ms vs 804.9ms = **2.50x**。
- 大负载系统性优势：大形状 2~3x，深层瘦条 **5.3x**，VGG-large 2.1~2.5x，batch 1.4~2.4x。
- 修复前输的 9~10 个形状**全部翻赢**：小通道窄 M/K（1.6~2.4x）与深层 7² 族（1.9~5.3x）。
- 大形状 4,384,160²,384 折算 GEMM ≈ **960 GFLOPS / 16 核 ≈ SVE-512 峰值 94%**。
- 仅剩的 1.1~1.3x 窄幅全部是 <1.1ms 的微小负载（1,16,224²,16 / 1,32,112²,32 / 1,8,16²,8 …），绝对差可忽略。

## 散写修复（bfd6b1e）的验证

同作业内：E3（新码，无 debug）vs E5（旧码 c48761e 快照，无 debug）——5 个 mini 形状：

| shape | 新（E3/新）ms | 旧（E5）ms | 结论 |
|---|---|---|---|
| 4,384,160²,384 | 71.995 | 70.522 | 平（1.02x 噪声） |
| 1,512,7²,512 | 2.703 | 2.927 | 新略快 |
| 1,2048,7²,512 | 11.179 | 11.091 | 平（预测 62→~12ms **兑现**） |
| 4,768,20²,96 | 3.801 | 4.420 | 新快 1.16x |
| 4,96,20²,96 | 0.448 | 0.503 | 新快 1.12x |

新码回到旧 pack 路径水平、小形状还反超；深层 1,2048 从散写回归的 62~65ms 回到 ~11ms，与 OB 的 59.7ms 形成 **5.3x**。深层族（1,512 7²/14²/28²）从修复前的「微输 OB」全部翻成 4.8~5.3x 大赢。

> ⚠️ **E1 计时陷阱**：E1 是带 `WINO_GEMM_DEBUG=1` 跑的（为了可视化选核），per-call 调试/选核开销会**不成比例地放大小形状**（同形状 4,768,20²,96：E1 6.00ms vs E3 3.80ms）。所以任何「新旧/大小」计时对比都必须用**无 debug** 的 E3/E5，E1 只当选核可视化看。

## oneDNN（ACL wino）对照怎么做

本表是「我们（arm_gemm 53.1.0 端到端） vs OpenBLAS 后端」的同作业对照，用于证明**后端切换收益**。与 **oneDNN / ACL wino** 的对照是另一条线，公平口径见 `docs/why_faster_than_acl_23.11.md` §10.4（同绑核 + 同实现 + primitive 跨迭代复用）：

```bash
# 我们侧（无 debug，bind）——已是 E3 的产物，重跑一遍直接落盘
OMP_PROC_BIND=close OMP_PLACES=cores bash tools/compare.sh --threads 16 shapes/conv_all.csv

# oneDNN 端到端（format_any，primitive 复用）—— tools/onednn/run_onednn_e2e.sh
# oneDNN benchdnn（同一描述符清单）—— tools/onednn/run_benchdnn.sh
```

工具链：`tools/onednn/`（onednn_e2e.cpp + 4 个 shell），描述符清单 `shapes/conv_all.list` 已就绪。
一条命令跑全套：`sbatch -w node03 --exclusive --wrap="bash tools/onednn/ab_onednn.sh"`
（单作业 A/B：ours / e2e / benchdnn WINO+auto / filter_sweep / 合并表）。
产出四列合并表 `mb,ic,ih,iw,oc,ours_ms,onednn_e2e_ms,benchdnn_wino_ms[,benchdnn_auto_ms]`
（`tools/onednn/merge_onednn.sh`）。**数据/工具/判读（含 e2e OOM 根因）的权威文档 =
`docs/onednn_comparison.md`**。把集群输出贴回来即可合并判读。
